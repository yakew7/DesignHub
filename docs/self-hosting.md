# Self-hosting

DesignHub is a Next.js 16 app whose pages are all prerendered. It has no database, no backend for your work and no secrets, so running your own copy only needs Node and a place to serve the build.

## Before you start

- **Node 22 or newer** (see `.nvmrc`) and **pnpm 11** (the exact version is pinned in the `packageManager` field of `package.json`; `corepack enable` installs it for you).
- **No environment variables or API keys are needed.** Every external service DesignHub calls (Google Fonts, Iconify) is public and keyless, and your work is stored in each visitor's browser, not on your server.
- **Optional:** set `NEXT_PUBLIC_SITE_URL` to your public URL (no trailing slash) so canonical links, `sitemap.xml`, `robots.txt` and social previews point at your domain instead of `https://designhub.dev`. It is read at build time, so set it before `pnpm build`. See `.env.example`.
- **Analytics are off outside Vercel.** `app/layout.tsx` only renders Vercel Web Analytics when the `VERCEL` variable is set, which Vercel does on its own builds. A self-hosted copy loads no analytics script and sends nothing. To remove analytics from a Vercel deployment too, delete `<Analytics />` from `app/layout.tsx`.
- **The service worker is generated by the build.** `pnpm build` runs `next build` and then the `postbuild` script (`scripts/generate-service-worker.mjs`), which writes `public/sw.js` for that build. Always build with `pnpm build`, not `next build` on its own, or the offline cache won't exist (the app still works, it just can't reopen offline). `public/sw.js` is gitignored; don't commit it.
- Service workers only register over **HTTPS** (or on `localhost`), so put a TLS-terminating proxy in front of a Node or Docker deployment if you want offline support.

## Vercel

1. Fork [the repository](https://github.com/yakew7/DesignHub) on GitHub.
2. In Vercel, choose **Add New... > Project** and import your fork.
3. Keep the detected defaults: framework **Next.js**, install command `pnpm install`, build command `pnpm build`, Node.js **22.x** (Project Settings > Build and Deployment). Vercel picks pnpm from `pnpm-lock.yaml` and `packageManager`.
4. Optionally add `NEXT_PUBLIC_SITE_URL` under Settings > Environment Variables.
5. Deploy. Every push to your default branch redeploys, and pull requests get preview URLs.

To count page views, open the project's **Analytics** tab and enable Web Analytics. No key is involved.

From the command line instead:

```bash
pnpm dlx vercel        # link the folder and create a preview deployment
pnpm dlx vercel --prod # deploy to production
```

## A plain Node server

On any Linux, macOS or Windows machine with Node 22:

```bash
git clone https://github.com/yakew7/DesignHub.git
cd DesignHub
corepack enable                 # provides the pinned pnpm version
pnpm install --frozen-lockfile
pnpm build                      # next build, then writes public/sw.js
pnpm start                      # serves on http://localhost:3000
```

To pick the port and listen on every interface (for example behind nginx or Caddy):

```bash
pnpm start -p 8080 -H 0.0.0.0
```

`pnpm start` is `next start`, a long-running process. Keep it alive with your usual process manager, for example a systemd unit with `ExecStart=/usr/bin/pnpm start -p 3000` and `WorkingDirectory=` set to the checkout, or `pm2 start "pnpm start" --name designhub`.

To update:

```bash
git pull
pnpm install --frozen-lockfile
pnpm build
# then restart the process
```

Each build gets a new build ID, and the service worker replaces the previous version's caches and offers visitors a reload.

## Netlify

Netlify detects Next.js and deploys it with its Next.js runtime, so no adapter needs to be installed.

1. Choose **Add new site > Import an existing project** and pick your fork.
2. Set the build command to `pnpm build` and the publish directory to `.next`.
3. Set the Node version to 22 (Netlify reads `.nvmrc`, or set `NODE_VERSION=22`). If the build uses an older pnpm, set `PNPM_VERSION` to the version in `package.json`'s `packageManager` field.
4. Optionally set `NEXT_PUBLIC_SITE_URL`, then deploy.

The same settings as a `netlify.toml` in the repository root:

```toml
[build]
  command = "pnpm build"
  publish = ".next"

[build.environment]
  NODE_VERSION = "22"
```

## Docker

A multi-stage image: dependencies are installed and the app is built in throwaway stages, and the final image only holds production dependencies and the build output. Save this as `Dockerfile` in the repository root:

```dockerfile
# syntax=docker/dockerfile:1

FROM node:22-alpine AS base
WORKDIR /app
ENV NEXT_TELEMETRY_DISABLED=1
# Installs the pnpm version pinned in package.json's packageManager field.
RUN corepack enable

# All dependencies, for the build.
FROM base AS deps
COPY package.json pnpm-lock.yaml pnpm-workspace.yaml ./
RUN pnpm install --frozen-lockfile

# Production dependencies only, for the final image.
FROM base AS prod-deps
COPY package.json pnpm-lock.yaml pnpm-workspace.yaml ./
RUN pnpm install --frozen-lockfile --prod

# The build: next build, then postbuild writes public/sw.js.
FROM base AS build
ARG NEXT_PUBLIC_SITE_URL
ENV NEXT_PUBLIC_SITE_URL=$NEXT_PUBLIC_SITE_URL
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN pnpm build

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production NEXT_TELEMETRY_DISABLED=1
COPY --from=prod-deps --chown=node:node /app/node_modules ./node_modules
COPY --from=build --chown=node:node /app/package.json /app/next.config.ts ./
COPY --from=build --chown=node:node /app/.next ./.next
COPY --from=build --chown=node:node /app/public ./public
USER node
EXPOSE 3000
CMD ["node_modules/.bin/next", "start", "-H", "0.0.0.0", "-p", "3000"]
```

And a `.dockerignore` next to it, so your local `node_modules` and build output aren't copied into the image:

```text
.git
.next
node_modules
public/sw.js
.env*
```

Build and run it:

```bash
docker build -t designhub .
docker run --rm -p 3000:3000 designhub
```

Open [http://localhost:3000](http://localhost:3000). To bake in your public URL, pass it at build time:

```bash
docker build --build-arg NEXT_PUBLIC_SITE_URL=https://design.example.com -t designhub .
```

## Checking your deployment

- The home page and every studio (`/brand`, `/colors`, `/typography` and so on) load, and `/sw.js`, `/sitemap.xml` and `/robots.txt` return 200.
- In DevTools, **Application > Service Workers** shows `sw.js` as activated (HTTPS or localhost only).
- **Network** shows no request to `/_vercel/insights` unless you are on Vercel.
- Your data lives in each visitor's browser, so moving to a new host or domain starts with empty projects. Visitors can carry their work across with Export and Import in Brand Projects (see the [storage guide](storage.md#back-up-your-work)).
